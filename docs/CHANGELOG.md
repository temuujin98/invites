### Сонгосон дэвсгэр урилга дээр гарахгүй байсан (алдаа)
`styles.css` доторх `.pv.layout-letter { background-image: none !important }`
нь `PublicInvitation`-ий тавьсан зургийг шууд устгаж байсан. Дэвсгэр сонгогч
нэмэгдэхэд JS тал нь `photoBackdrop(layout) || isInvitationBackground(...)`
гэж letter-д ч зөвшөөрдөг болсон боловч CSS-ийн `!important` reset хэвээр
үлдсэн — өөрөөр хэлбэл JS «үзүүл» гэж, CSS «үзүүлэхгүй» гэж байсан.

Reset-ийг `:not(.has-bg)` болгож нарийвчлав. Дэвсгэр сонгосон үед дугтуйны
градиент нь тунгалаг болж (`color-mix`), зураг нь захаас харагдана.
`lavender-wedding` бол `layout: 'letter'` цорын ганц загвар тул алдаа зөвхөн
түүнд илэрч байсан.

### Зураг WebP болов — 33MB → 3.3MB
PNG-ийг `scripts/optimize-backgrounds.mjs`-ээр хоёр WebP болгож хөрвүүлэв:
бүтэн хэмжээ (зочны хуудсанд) + 400px thumb (picker-т). PNG эх файл
хадгалагдахгүй — `scripts/generate-backgrounds.sh` (Codex prompt-ууд)-аар
дахин үүсгэнэ. Picker-ийн ачаалал **33MB → 550KB**.

  театрт ч тэгдэг.

хөшигний дүр. Манайх хаалттай үедээ дэлгэцийг бүтэн таглах ёстой (эс бөгөөс
урилга ард нь харагдана) тул түүнийг шууд хуулаагүй.

## 2026-08-04 — Intro дахин барив, захидлын загвар, скролл animation

### Intro (хөшиг, захиа) — чанарын хувьд дахин барив
Хуучин хөшиг нь тэгш 104px давтамжтай `repeating-linear-gradient` байсан тул
даавуу биш штрих код шиг харагддаг байв. Зассан:
- Атирааны давтамжийг **тэгш бус 146px** болгож, өнгөний шилжилтийг зөөлрүүлэв
- Хоёр тал бариулын үзүүр рүү **бөөгнөрөн** хураагдана (`scaleX` + гадна тал
  `transform-origin`), баруун тал **0.1 сек хоцорно** — тэгш хэм алга болов
- Алтан бариул, дотор ирмэгийн металл ирмэг, даавуун дээгүүр тунгалаг гялбаа
- Задрахад төвөөс тайзны гэрэл асна
- Захианд: **хавхлагийн сүүдэр захидал дээр унана** (цаасны зузааныг мэдрүүлдэг
  гол зүйл), `drop-shadow`-оор цаасны ирмэг, гүдгэр лац

### Тоосонцор — `invite/intro/particleField.js`
Номын сангүй canvas хөдөлгүүр, 6 preset: дэлбээ · confetti · оч · алтан тоос ·
одод · хөөс. Загварын tone-оор автоматаар сонгогдоно. Гар утсанд нягтрал
автоматаар хагасална. **Нийт +2.4KB** (Three.js байсан бол +170KB).

Хөшигний өнгөнд «Загварын өнгө» (`auto`) сонголт нэмэгдэж анхдагч болов.

### Захидлын загвар — `layout: 'letter'`
Дугтуйнаас татагдаж буй цайвар захидал. Дугтуйны урд тал `position: fixed`-ээр
доод талд зогсож, захидал ард нь дээш гүйнэ. **Захидлын дотор тусдаа скролл
хийгээгүй** — гар утсанд давхар скролл хуруутай зөрчилддөг.
`lavender-wedding` үүн рүү шилжсэн; `rose-wedding` нь өмнөх ёслолын загвартай
хэвээр — харьцуулж сонгохын тулд.

### Чимэглэл — SVG (`docs/ORNAMENT-ASSETS.md`)
Сүлжмэл ирмэг, навчит мөчир (давтагдах, CSS `mask`), булан, тусгаарлагч,
лацны хээ (inline React SVG). **Нийт ~2.2KB.** Нэг ассет 12 загварт — өнгө нь
`background-color` / `currentColor`-оос ирнэ. Давтагдалтын залгаасыг геометрээр
шийдсэн (дэлгэрэнгүйг баримтад).

### Скролл дагасан animation — `invite/useReveal.js`
`IntersectionObserver` + CSS, **+0.24KB**. Хэсгүүд доороос хөвж гарна, мөрүүд
80ms зөрүүтэй ээлжилнэ.

⚠️ **Аюулгүйн зарчим**: урилга бол бүтээгдэхүүн өөрөө учир үл үзэгдэх болох
ёсгүй. Хэсгүүд JS `reveal-armed` класс нэмтэл **энгийн харагдана**, мөн 2.5
секундын нөөц таймер observer ажиллаагүй тохиолдолд бүгдийг нээнэ.

### Засварууд
- **Зургийн цомог гүйлгэгддэггүй байсныг зассан.** Зурагт `width` ч,
  `aspect-ratio` ч байгаагүй тул ачаалагдтал 0px өргөнтэй байж, гүйлгэх зай
  үүсэхгүй → `loading="lazy"` зураг дэлгэцэнд орохгүй → ачаалагдахгүй гэсэн
  тойрог хаалт үүсч байв. `aspect-ratio: 4/3`-аар зай нөөцлөв.
  Гүйлгэх зай **20px → 650px**.
- `isWeddingTemplate` нь layout биш **арга хэмжээний төрлөөр** шалгадаг болов —
  хурим ямар ч загвартай байсан эцэг эх, ёслолын цагийн талбарууд ажиллана.

## 2026-08-03 — Хуримын загвар: тусдаа layout (Монгол ёслолын сүр жавхлан)

Өмнө нь 12 загвар бүгд **нэг л** зочны хуудсаар рендерлэгддэг байсан — ялгаа нь зөвхөн accent өнгө, гарчгийн фонт, фон зураг. Загвар бүр өөрийн бүтэцтэй байх боломжийг нээж, эхнийхийг нь хуримаар хийв.

### Архитектур
- `client/src/invite/shared.jsx` — бүх layout-д хуваалцах хэсгүүд (дуу, хөшиг/захидлын intro, тооллого, цомог, RSVP форм)

- `PublicInvitation.jsx` нь ачаалагч + dispatcher болов; `templates.js` дэх `layout` талбараар layout сонгогдоно

### Хуримын хуудсанд шинээр
- Хосын хоёр нэр толгойд том serif-ээр, дунд нь алтан монограм
- Хүргэн/бэрийн эцэг эхийн нэр хүндэтгэлтэйгээр
- Ёслолын ажиллагаа ба хуримын найр **тусдаа цаг, тусдаа байршилтай**
- Огнооны хавтан: гараг · өдөр · сар/жил
- Хувцаслалтын хэсэг
- Алтан хос хүрээ, ёслолын чимэглэл — захидал/хөшгийн intro-той нэг өнгө аястай

- `WeddingFields.jsx` — хосын нэр, эцэг эх, ёслолын цаг/газар, хувцаслалт. Зөвхөн хуримын загвар сонгосон үед харагдана

## 2026-07-23 — Системийн бүрэн шинэчлэл (funnel rebuild)

Бүх урсгалыг эхнээс нь шинээр хийв. Гол зарчим: маш энгийн, function бүр төгс ажилладаг.

### Хэрэглэгчийн урсгал
1. **Landing** (`/`) — hero + header баруун буланд «Урилга үүсгэх» товч л бий
2. **Загвар сонгох** (`/create`) — 6 загвар, загвар бүр өөрийн үнэтэй
3. **Мэдээлэл оруулах** (`/create/:templateId`) — нэр, огноо, байршил, мессеж + live preview; ноорог localStorage-д хадгалагдана
4. **Имэйл баталгаажуулалт** (`/create/confirm`) — Gmail magic link; бүртгэл автоматаар үүснэ; session ороход ноорог DB-д бичигдэнэ (утас/SMS дараа нэмэгдэнэ)
5. **Төлбөр** (`/pay/:id`) — одоогоор mock (шууд амжилттай); Bonum холболт `payMock()` функцийг сольж хийгдэнэ
6. **Амжилт** — `/i/:slug` шууд идэвхжинэ, холбоос хуулах

### Хэрэглэгчийн хэсэг
- `/my` — өөрийн урилгууд: төлөв, төлбөр, RSVP хариунууд (нэр, хүний тоо). Илүү feature зориуд байхгүй.
- `/i/:slug` — зочны хуудас: загварын өнгөөр, зочны нэр + хүний тоотой RSVP

### Admin (`/admin`)
- Тусдаа dashboard (app workspace): орлого, идэвхтэй урилга, хүлээгдэж буй төлбөр, нийт RSVP
- Урилгын хүснэгт: төлөгдсөн болгох / түр хаах / идэвхжүүлэх / архивлах
- Төлбөрийн хүснэгт
- Хандалт: `public.admins` хүснэгтэд бүртгэлтэй хэрэглэгч л орно

### DB (Supabase, migration applied)
- `invitations`: + `template_id`, `options`, `price`, `owner_email`; status-д `pending_payment` нэмэгдсэн
- `payments` (шинэ): amount, method (mock/bonum), status (pending/paid/failed) + RLS
- `admins` (шинэ) + `is_admin()` security definer function; админ эрхийн RLS бүх хүснэгтэд
- `invitations`-д authenticated-д insert/update/delete grant нэмсэн (RLS хамгаална)
